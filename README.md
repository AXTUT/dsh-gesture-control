# dsh-gesture-control · DSH 手势控制

用普通摄像头和单手手势操作 DSH 会话：握拳停止、张掌口述、拇指发送或撤销、数字答题、手势浏览会话。同时提供基于 [DualTransfer](<https://github.com/AXTUT/dsh-plugin-dualtransfer-trial>) 配对的双端控制。第三方非官方插件，插件代码 MIT，免费使用；手势模型和 WASM 随包提供，识别在本机 Worker 中进行。

**0.1.7 已扩展到 DSH 0.2.2：兼容范围为 `>=0.2.1-rc.2 <0.2.2-0 || >=0.2.2-rc.1 <0.2.3-0`，不再只允许安装到 0.2.1-rc.2。** 该范围保留同一 minor 的后续 rc/stable，明确排除 0.2.2 alpha、0.2.3 alpha 和更高 minor；后续版本属于兼容策略，并非逐版实机验收。接口核验、回归与边界见 [兼容说明](<COMPATIBILITY.md>)。Node.js 还须满足所用 Harness 自身要求，例如 0.2.2-rc.5 要求 ≥24.9.0。

**摄像头权限前提仍在：** 原版 Windows Desktop 0.12.1 拦截摄像头/麦克风的 `media` 权限，会遇到 `NotAllowedError`，须由桌面维护者合入对应的 [媒体权限补丁](<desktop/README.md>)。其他 Desktop 版本以其自身媒体权限实现为准，不应直接套用旧版补丁；插件不会修改宿主。真实 Host、macOS/Windows 设备、真实双机和真人手势全流程仍待验证。浏览器入口可用于进一步调试，发布检查不等于桌面实测。

比如，AI 正在写代码，你瘫在椅子上刷手机，不想再凑到键盘前。看到它跑偏了，抬手握拳叫停；想补一句要求，就张掌口述、握拳结束，检查草稿后再比个 👍 发出去。这是插件设想的一个使用场景，前提是摄像头能看清手，并已开启识别、勾选“接入 DSH 动作”。

## 安装与首次开启

- npm 包：[`dsh-gesture-control@0.1.8`](https://www.npmjs.com/package/dsh-gesture-control)。在 DSH 插件管理的安装入口填入这个精确包版本。
- 本地包：从 [GitHub Releases](https://github.com/AXTUT/dsh-gesture-control/releases) 下载 `.tgz`，在 DSH 插件管理的“安装包/本地包”入口选择它。启用 `gesture-control`。
- 普通 `npm install` 只会安装文件，不会替 DSH 完成插件启用；无需在现用 profile 中手改配置。

1. 先满足上面的桌面权限前提，再打开右上“✋ 手势控制”，点“开启手势”。默认仅预览，勾选“接入 DSH 动作”才执行操作。
2. 使用口述前，启用官方 `@deepseek-ai/dsh-experimental-voice-input-bundle`，并在语音设置中确认当前所选提供方。希望音频本地处理时，选择本地 SenseVoice。点“准备语音模型”，在官方语音设置看进度；首次可能联网下载模型，随后使用本机缓存。插件遵循 DSH 当前语音选择；若选云端提供方，音频会交给该服务。没有语音组件时仍可使用手势预览、停止和导航。
3. “收起控制栏”只收卡片，仍显示手形、方向和录音状态；工具条“−”会最小化全部插件内容，只留右侧 ✋ 恢复按钮。两者都继续识别；最小化也保留已打开的列表场景，1/2/握拳仍操作该列表，恢复后可见。重载会回到默认收起状态，不持久化设备或授权开关。
4. 点“停止识别并释放设备”关闭摄像头并取消当前口述，保留已有草稿；这不关闭已经允许的双机接收。关闭接收请取消相应接收勾选；插件卸载时才同时关闭两条链路。权限未获准时显示原因，可手动重试。
5. “使用说明”与“控制”是独立栏目，不开启摄像头也能先阅读。每个手势的场景差异、未分配动作、双机限制和语音数据去向均在其中。

## 手势速查

| 场景 | 手势 | 效果 |
| --- | --- | --- |
| 本轮执行中 | 握拳约 0.45 秒 | 停止本轮；不是可恢复暂停 |
| 普通会话 | 张掌 | 稳定识别后开始口述，看到“录音中”再说话 |
| 录音中 | 握拳 | 结束录音、转写、整理标点，再追加到原会话草稿 |
| 闲置会话 | 👍 约 0.65 秒 | 发送草稿；无草稿的已有任务发送可见的“继续” |
| 转写已进入草稿 | 👎 | 撤销最近一段完整转写，保留原稿和前几段 |
| 普通选择题 | 手指数 1–5 | 选择 DSH 原题目的对应选项；五指是 5，不录音 |
| 多选或超过五项 | 上下滑、握拳 | 浏览高亮，握拳选中；多选再握拳统一提交，先解除姿态 |
| 普通会话或答题中 | 🤟 保持约半秒 | 打开或收起会话列表 |
| 会话列表 | ☝ 1 / ✌ 2 | 上一条 / 下一条；同姿态只移动一次，放下手再做 |
| 会话列表 | 握拳 | 进入高亮会话 |
| 双端连接 | 🤙 保持约半秒 | 切换本机 / 已确认配对的对端 |

选第三项可伸食指、中指、无名指；🤟 专用于列表。滑动方向以镜像预览为准。权限审批和计划审批仍走 DSH 原界面。

**插件小窗的收起/最小化继续识别；宿主窗口最小化或切后台则以页面 `document.hidden` 为准：** 页面隐藏会暂停本机摄像头取帧，结束正在进行的录音并继续转写；恢复后先放下手约 250ms。已允许的双机接收不会仅因页面隐藏而关闭。新按钮保留正常键盘焦点；跨屏、无焦点和 Windows 具体窗口行为仍待真人验证。麦克风仅录音时打开，摄像头一次处理一帧，目标约 10 fps，不是本轮性能实测。

## 双端控制：先配对，再确认

双端控制需另装 [DualTransfer 双机通信插件](<https://github.com/AXTUT/dsh-plugin-dualtransfer-trial>)，安装、配对和会话绑定步骤见其仓库说明。

两台 DSH 安装本版插件，分别在目标会话完成 DualTransfer 配对和绑定，并确认能收发。接收端勾选“允许配对设备连接当前 Dual 会话”，接收端无需摄像头。发送端开启手势并接入动作，比 🤙；核对两边的八位校验码，由接收端点允许。出现“目标：对端”后才操作，再比 🤙 返回本机。

对端模式下，握拳请求停止已绑定会话；张掌仍在发送机录音，握拳结束后文字进入独立的“对端文字草稿”。可手改、续录或 👎 撤销，👍 才提交给对端。空草稿的 👍 表示继续。数字答题和会话列表在对端执行，浏览列表不会重新绑定 Dual。权限审批留给接收端用户。

连接协商通过已有 Dual 消息传递 WebRTC offer/answer，消息在 Dual 历史可见。建立后，局域网数据通道传手势指令和确认提交的文本，不通过该通道传摄像头画面或录音；音频的处理位置另取决于所选语音提供方。接收端取消勾选会断开连接；掉线或绑定变化会提示，不会悄悄改成操作本机。当前发布没有真实双机验收报告。

## 数据流向

- 手势视频：本机 Worker 推理，模型/WASM 同源加载，使用期不走 CDN。
- 录音：交 DSH 当前所选语音提供方转写，选择本地 SenseVoice 时音频在本机处理；若选云端提供方则发送给该服务，首次模型准备也可能联网。
- **录音结束后，转写文本自动交给 DSH 当前默认模型整理标点，不必等 👍 提交。默认 provider 若是远程服务，该段文本会发送给该服务；这一步不保证离线。** 超时或检测到字词变化时回退原转写。
- MediaPipe 官方隐私声明还提到性能/使用指标。插件未配置远程遥测不等于 SDK 保证零遥测；本次发布没有做完整流量验收。参见 [官方隐私说明](https://goo.gle/mediapipe-privacy) 和 [随包声明](<assets/MEDIAPIPE_README.md>)。
- 👍 发送后的会话内容按 DSH 本身的模型配置处理。双端控制还会把确认提交的文字发送给配对设备。

录音开始时锁定 session ID，鼠标切到另一会话也将结果追加到原会话的最新草稿，保留中途手改。转写未完成时拇指不发送旧草稿。题目绑定原 session/request/question，鼠标已回答的旧题不带到新题。列表沿用当前版本的工作区可见范围和侧栏顺序，排除归档与子会话。这些为实现行为说明，不代表本轮真人场景均已验收。

```sh

```
